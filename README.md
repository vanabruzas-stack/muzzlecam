# Muzzle Zoom

Нативная камера для базового iPhone 17 с iOS 27. В архиве есть Xcode-проект, исходники SwiftUI, AVFoundation, Core Image и Metal, две предобученные модели Core ML и сценарий GitHub Actions для сборки неподписанного IPA. Для сборки с Windows 11 достаточно Git и доступа к GitHub. Камера обрабатывает кадры на устройстве и работает офлайн.

Проект опубликован в `vanabruzas-stack/muzzlecam`. Готовый IPA версии 1.1 для Bundle ID `com.muzzlezoom.camera` доступен в разделе **Artifacts** успешного запуска. Если ваш профиль разрешает этот идентификатор, скачайте IPA и переходите к разделу 3. Если профиль привязан к другому идентификатору, запустите сборку с этим Bundle ID по инструкции в разделе 2. [Успешный запуск Build unsigned IPA](https://github.com/vanabruzas-stack/muzzlecam/actions/runs/44124245180)

## 1. Загрузка проекта на GitHub с Windows 11

1. Распакуйте `MuzzleZoom-project.zip`, например в `C:\Projects`. В папке `MuzzleZoom` должны быть `MuzzleZoom.xcodeproj`, `App`, `Scripts` и `.github`. Папку `.github` нужно сохранить.
2. Установите **Git for Windows**. Откройте Windows Terminal или PowerShell и проверьте командой `git --version`. [Git for Windows](https://gitforwindows.org/)
3. В GitHub создайте пустой репозиторий `MuzzleZoom`. Для личного проекта выберите **Private**. При создании пропустите добавление README, .gitignore и лицензии.
4. В PowerShell выполните команды ниже. Замените путь, если распаковали архив в другое место, и подставьте своё имя пользователя GitHub вместо `YOUR-USERNAME`.

```powershell
Set-Location -LiteralPath 'C:\Projects\MuzzleZoom'
git init -b main
git add .
git status --short
git commit -m "Add Muzzle Zoom iOS project"
git remote add origin https://github.com/YOUR-USERNAME/MuzzleZoom.git
git push -u origin main
```

Git может открыть окно входа в GitHub. Если при первом коммите Git попросит имя и адрес автора, задайте их для текущего репозитория командами `git config user.name "Ваше имя"` и `git config user.email "ваш-адрес"`, затем повторите коммит и отправку. [Импорт локального проекта в GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github?platform=windows)

Профиль, сертификат и пароль к нему понадобятся только на iPhone. В GitHub Actions используются исходники и встроенные веса моделей.

## 2. Сборка и скачивание IPA

1. После отправки ветки `main` откройте вкладку **Actions** → **Build unsigned IPA**. При отключённых Actions включите их в репозитории. Сценарий использует GitHub-hosted runner `xcode-27` на Apple Silicon и SDK iOS 27. [Образ GitHub Actions для Xcode 27](https://github.blog/changelog/2026-10-15-xcode-27-runner-image-generally-available/)
2. Если ваш provisioning profile разрешает конкретный Bundle ID, запустите **Run workflow** и укажите этот идентификатор в поле `bundle_id`, например `com.yourname.muzzlezoom`. Автоматический запуск использует `com.muzzlezoom.camera`. При каждом обновлении установленного приложения используйте тот же Bundle ID и совместимый профиль.
3. Откройте успешный запуск и скачайте **Artifacts → MuzzleZoom-unsigned**. Распакуйте ZIP из GitHub. Внутри лежат `MuzzleZoom-unsigned.ipa` и `SHA256SUMS.txt`. Артефакт хранится до 14 дней. [Скачивание артефактов GitHub Actions](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts)
4. Чтобы сверить контрольную сумму, откройте PowerShell в папке с IPA. Значения SHA-256 в выводе двух команд должны совпадать без учёта регистра.

```powershell
Get-FileHash -LiteralPath .\MuzzleZoom-unsigned.ipa -Algorithm SHA256
Get-Content -LiteralPath .\SHA256SUMS.txt
```

Если workflow завершился ошибкой, откройте шаг **Verify and build** и найдите первую ошибку. Сценарий проверяет веса, компилирует приложение под iPhone arm64 и тестирует обе модели на macOS перед упаковкой. GitHub покажет артефакт, когда все проверки пройдут. Если репозиторий принадлежит организации, доступ к runner и сторонним действиям может определяться её настройками.

При наличии Mac ту же сборку можно запустить командой `bash Scripts/build-ipa.sh dist` из корня проекта с выбранным Xcode 27.

## 3. Подпись и установка через ESign

Инструкция предполагает, что ваша копия ESign уже установлена и открывается на iOS 27. Названия пунктов меню могут отличаться в зависимости от версии ESign.

1. В `Файлы` на iPhone перенесите `MuzzleZoom-unsigned.ipa`, свой `.p12` с закрытым ключом и подходящий `.mobileprovision`. Для development или ad hoc профиль должен включать UDID этого iPhone, разрешать выбранный Bundle ID и соответствовать сертификату. Проверяйте срок действия профиля и сертификата. [Профиль Ad Hoc](https://developer.apple.com/help/account/provisioning-profiles/create-an-ad-hoc-provisioning-profile/), [профиль для разработки](https://developer.apple.com/help/account/provisioning-profiles/create-a-development-provisioning-profile)
2. В ESign импортируйте `.p12` и `.mobileprovision` через **Import**. При запросе введи́те пароль `.p12` прямо в приложении. В **Certificate Management** должна появиться ваша пара.
3. Импортируйте сам файл `.ipa`. В разделе приложений откройте карточку **Muzzle Zoom** и выберите **Signature** или **Sign**. Выберите свою пару, сверьте Bundle ID с профилем и запустите подпись.
4. В разделе подписанных приложений выберите **Install** и подтвердите установку iOS. Если iOS требует режим разработчика, откройте **Настройки → Конфиденциальность и безопасность → Режим разработчика**, включите переключатель, перезапустите телефон и подтвердите действие. [Режим разработчика](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)
5. Откройте Muzzle Zoom и разрешите доступ к камере. При первом снимке разрешите добавление в «Фото».

Если ESign подписал IPA, но iOS отклоняет установку, проверьте соответствие Bundle ID, UDID, профиля и сертификата. Если подпись проходит, а кнопка установки не срабатывает, проверяйте совместимость вашей версии ESign с установленной версией iOS. Совместимость ESign и установка на iPhone в этой среде не проверялись.

## Режимы съёмки

| Режим | Обработка |
| --- | --- |
| **Quality Zoom, 1×–10×** | Основная Fusion Main, нативное кадрирование до поддерживаемого предела и последующее цифровое кадрирование. Приоритет качества AVFoundation, шумоподавление, коррекция локальной резкости и тонов. Если видоискатель обнаруживает контрастную сцену и устройство поддерживает брекетинг, камера пытается объединить нормальную и короткую экспозиции. |
| **AI Super Zoom, 10×–30×** | При доступном бюджете производительности видоискатель использует Real-ESRGAN. Снимок обрабатывается отдельной моделью и может использовать до трёх совмещённых кадров. |
| **Extreme Zoom, 30×–200×** | Кадрирование с пресетами 120×, 150× и 200×, гироскоп, совмещение кадров, восстановление по субпиксельным смещениям и умеренное нейроулучшение. Доля нейросетевого слоя снижена, поскольку маленький фрагмент сенсора содержит мало независимых отсчётов. |

У базового iPhone 17 основная камера имеет сенсорную оптическую стабилизацию и режим 2× с оптическим качеством. Программа удерживает центр цифрового кадра по опорному изображению. При потере захвата центр остаётся на последней позиции, одиночный скачок оценки игнорируется. Гироскоп помогает распознать намеренный поворот телефона. Кнопка с ладонью отключает программную стабилизацию. Включите **Zoom Lock** и коснитесь объекта, чтобы перенести область удержания. На 2× и выше спуск работает без виброотклика. [Спецификации iPhone 17](https://www.apple.com/iphone-17/specs/), [нативные коэффициенты AVFoundation](https://developer.apple.com/documentation/avfoundation/avcapturedevice/format/secondarynativeresolutionzoomfactors)

Видоискатель показывает кадр 4:3. При Quality 1× приложение запрашивает максимальный размер в режиме AVFoundation `.photo` и сохраняет пиксели всего кадра, который вернула камера. Доступность 48 Мп определяет iOS по сцене и условиям съёмки. После сохранения интерфейс показывает фактический размер готового файла. [Съёмка в высоком разрешении в AVFoundation](https://developer.apple.com/videos/play/wwdc2026/304/)

Итоговые файлы сохраняются как HEIC Display P3 с контролируемым тональным диапазоном SDR. При недоступности HEIC сохраняется обработанный JPEG. Для высоких зумов длинная сторона ограничена 3072 пикселями в AI Super и 1792 в Extreme. Выходное разрешение отражает размер файла, а фактическая детализация зависит от исходной области сенсора. Приложение сообщает о неподдерживаемом ИИ, неполной серии и переходе на обработку одного кадра. Если обработка или сохранение невозможны, оно показывает ошибку.

При нагреве или давлении на камеру отключается нейроулучшение и сокращается серия. При долгом инференсе видоискатель временно переключается на Core Image. В JPEG/HEIC нет отметки на самом изображении. Статус применения ИИ отображается в интерфейсе.

## Реализовано и требует проверки

- **В проекте реализовано**. Нативный захват фото и видео для предварительного просмотра, ручная компенсация экспозиции и фокус по касанию, стабилизация, режимы зума, два конвейера, сборка с зафиксированными весами. Металлический вычислительный шейдер использует веса соседних отсчётов, совмещает резкие участки и отбрасывает расходящиеся, чтобы сократить двоение на движении. Браузер фотографий использует системный Photos Picker.
- **Экспериментальная диагностика**. Экран сведений проверяет `VTLowLatencySuperResolutionScalerConfiguration.isSupported` и доступные масштабы для кадра 640 × 480. Обработка в релизном конвейере использует встроенный Core ML, поэтому работает без скачивания системной модели VideoToolbox. [VideoToolbox](https://developer.apple.com/documentation/videotoolbox/vtlowlatencysuperresolutionscalerconfiguration)
- **Требует проверки на устройстве**. Установка через ESign, совместимость конкретного формата камеры с экспозиционным брекетингом, эффективность Zoom Lock на 100×–200×, реальный FPS и производительность A19. Сравнение с Samsung Ultra и показатели детализации на 200× не измерялись.

GitHub Actions собрал IPA для iPhone arm64 на Xcode 27.1. На macOS прошли тесты совмещения, кадрирования и подавления синтетической дрожи, а также инференс обеих моделей через нативный Core ML. Скачанный IPA проверен на целостность и отсутствие подписи и provisioning profile. [Журнал сборки](https://github.com/vanabruzas-stack/muzzlecam/actions/runs/44124245180/job/134183565402)

После первой установки полезно снять одну сцену с мелким текстом на 1×, 2×, 10×, 30× и 200×, переключить ИИ на 30×, проверить Zoom Lock на 120× и снять человека в движении в AI Super. Для проверки HDR используйте неподвижную высококонтрастную сцену с ярким окном и тенями, с EV на нуле. Сравните видоискатель с сохранённым кадром и проверьте повторный запуск камеры после сворачивания.

## Модели и исходники

- **Real-ESRGAN**. В `App/Models` включены две версии одной модели `realesr-general-x4v3` 4× с FP16-весами. Входы 48×48 для видоискателя и 128×128 для снимка. Для фото используются плитки с запасом 34 пикселя от границ. Модель обучена авторами Real-ESRGAN, которые публикуют веса и исходники под BSD-3-Clause. Копия лицензии поставляется с проектом и приложением. [Репозиторий Real-ESRGAN](https://github.com/xinntao/Real-ESRGAN), [официальный файл весов](https://github.com/xinntao/Real-ESRGAN/releases/download/v0.2.5.0/realesr-general-x4v3.pth)
- **Core ML Tools**. `Scripts/convert_models.py` проверяет SHA-256 исходного чекпойнта и воспроизводит конвертацию с `coremltools==9.0` и NumPy. Для обычной сборки Python и PyTorch не нужны, так как обе модели в архиве. Проверка SHA-256 встроена в сценарий сборки. [Core ML Tools](https://github.com/apple/coremltools)
- **Deep Burst SR**. Рассмотрен опубликованный подход к регистрации и восстановлению из серии кадров. Приложение использует собственное совмещение обработанных кадров AVFoundation. Весам Deep Burst SR требуются серии RAW и отдельная подготовка Bayer-данных. [Deep Burst SR](https://github.com/goutamgmb/deep-burst-sr)
- **NextLevel**. Использован как референс архитектуры захвата. Прямое подключение AVFoundation даёт доступ к фотонастройкам и видеобуферам выбранного формата без зависимости от стороннего медиаслоя. [NextLevel](https://github.com/NextLevel/NextLevel)
